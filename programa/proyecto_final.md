# Proyecto final aplicado a física

## Propósito

El proyecto demuestra la capacidad de formular y desarrollar una investigación
computacional pequeña pero seria. No se evalúa la cantidad de código ni el uso de
características avanzadas de Python: se evalúan la pregunta, la corrección, la
validación, la interpretación y el dominio individual.

Puede realizarse individualmente o en parejas. En parejas, cada integrante recibe
una nota individual de sustentación y debe poder explicar el sistema completo.

## Modalidades

### A. Modelado o simulación

Construcción de un modelo que requiera evolución, exploración de parámetros,
azar, optimización o comparación de aproximaciones. Debe contrastarse con un caso
analítico, un resultado publicado, datos o una implementación de referencia.

### B. Análisis de datos físicos

Análisis de datos experimentales u observacionales con decisiones justificadas de
limpieza, unidades, incertidumbre, visualización y ajuste o comparación de
modelos.

### C. Datos y base relacional

Diseño o uso de una base PostgreSQL con datos científicos, consultas SQL no
triviales y un análisis reproducible desde Python. Debe existir una pregunta
científica; almacenar y mostrar registros no constituye por sí solo un proyecto.

## Filtro de seriedad

Una propuesta no se aprueba si su resultado principal puede obtenerse mediante
una sustitución directa en una fórmula, un único gráfico sin análisis, un tutorial
copiado, una calculadora, un CRUD sin pregunta científica o una modificación
cosmética de un ejemplo de clase.

Para aprobar el alcance, la propuesta debe evidenciar al menos tres de los
siguientes elementos y siempre incluir validación:

- comparación entre modelos o algoritmos;
- barrido de parámetros y análisis de sensibilidad;
- datos reales con problemas de calidad;
- incertidumbre experimental o numérica;
- evolución temporal o componente estocástico;
- integración de varias fuentes o tablas relacionadas;
- resultado que requiera más de una etapa computacional;
- decisión científica sustentada en los resultados.

## Entregables

1. Propuesta de máximo dos páginas.
2. Repositorio Git con hitos identificables.
3. Programa ejecutable desde instrucciones limpias.
4. Datos permitidos o instrucciones verificables para obtenerlos.
5. Pruebas automatizadas y comprobaciones científicas.
6. Informe técnico breve o README científico equivalente.
7. Figuras con unidades, etiquetas y explicación.
8. `AI_USAGE.md`, incluso si declara que no se utilizó IA.
9. Demostración y sustentación individual.

## Evidencia mínima de validación

Todo proyecto debe incluir:

- al menos un caso cuyo resultado sea conocido o calculable independientemente;
- al menos una prueba de caso límite o comportamiento esperado;
- comparación cuantitativa, no solo visual;
- discusión de error, incertidumbre o limitación;
- explicación de por qué el resultado es físicamente plausible.

## Autenticación

Durante la sustentación el docente puede solicitar:

- explicar una función o consulta elegida al azar;
- predecir el efecto de cambiar una entrada;
- interpretar una prueba fallida;
- corregir un defecto pequeño;
- agregar un caso de prueba;
- justificar una decisión de modelado o datos;
- comparar el código entregado con una alternativa.

La incapacidad de explicar partes esenciales activa los límites establecidos en la
rúbrica, independientemente de la calidad aparente del repositorio.
